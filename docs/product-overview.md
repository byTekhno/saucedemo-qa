# Обзор продукта: Sauce Demo

Sauce Demo (в интерфейсе — **Swag Labs**) — учебный интернет-магазин. Чтобы попасть в каталог, нужно войти. Дальше пользователь выбирает товары, кладёт их в корзину и оформляет заказ.

Это не настоящий магазин: оплата фиктивная, доставка не происходит. Сайт сделан, чтобы практиковать тестирование.

## Зачем тестировать именно его

- Короткий, но полный e-commerce поток: логин → каталог → корзина → заказ
- Есть позитив, негатив и специально сломанные роли
- Легко объяснить рекрутеру: «я протестировал магазин от логина до thank-you page»

## Пользовательские роли

Все роли входят с одним паролем `secret_sauce`. Разница — в поведении после логина.

| Роль | Ожидаемое поведение |
|---|---|
| `standard_user` | Приложение работает штатно |
| `locked_out_user` | Вход запрещён, показывается ошибка |
| `problem_user` | Ломаются картинки, сортировка, поля формы |
| `performance_glitch_user` | Те же функции, но с заметной задержкой |
| `error_user` | Часть действий приводит к ошибке |
| `visual_user` | Функции могут работать, вёрстка — нет |

Для регресса и «счастливого пути» используем `standard_user`.  
Остальные роли — отдельные негативные и исследовательские прогоны.

## Карта приложения

```text
Login
  └─ Inventory (каталог, 6 товаров)
        ├─ Product details (карточка товара)
        ├─ Cart
        │     └─ Checkout: информация → обзор → complete
        └─ Бургер-меню: All Items / About / Logout / Reset App State
```

## Страницы и URL

| Страница | URL | Что проверяем |
|---|---|---|
| Логин | `/` | Вход, валидация, ошибки |
| Каталог | `/inventory.html` | Список, сортировка, Add to cart |
| Карточка товара | `/inventory-item.html?id=N` | Название, цена, описание, кнопка |
| Корзина | `/cart.html` | Состав, удаление, переход к чекауту |
| Чекаут, шаг 1 | `/checkout-step-one.html` | Имя, фамилия, индекс |
| Чекаут, шаг 2 | `/checkout-step-two.html` | Состав заказа, налог, итог |
| Успех | `/checkout-complete.html` | Сообщение и возврат в каталог |

Прямой заход на внутренние URL без логина должен возвращать на страницу входа.

## Главные риски

1. Негативный логин оформлен плохо (нет текста ошибки / можно войти без пароля)
2. Счётчик корзины расходится с реальным составом
3. Сортировка по цене или имени работает неверно
4. На чекауте можно продолжить с пустыми полями
5. Итог / налог посчитаны неправильно
6. После Logout остаётся доступ к каталогу (кнопка «Назад» в браузере)
7. Reset App State не очищает корзину
8. У «сломанных» пользователей нельзя отличить баг от задумки демо — это нужно явно писать в баг-репорте

## Что сознательно не тестируем сейчас

- Настоящая оплата и платёжный шлюз (их нет)
- Бэкенд API и база (чёрный ящик, только UI)
- Безопасность на уровне пентеста
- Локализация (интерфейс только на английском)
- Нагрузочное тестирование (кроме наблюдения за `performance_glitch_user`)
