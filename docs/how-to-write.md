# Как писать кейсы и баги

Короткие правила, чтобы репозиторий выглядел как работа QA, а не как список кликов.

## Тест-кейс

Один кейс = одна проверка. 

Обязательные поля:

- **ID** — стабильный, не меняем после прогона (`TC-LOGIN-001`)
- **Название** — что проверяем, а не как кликаем
- **Приоритет** — P0 / P1 / P2
- **Предусловие** — с какой страницы и под кем стартуем
- **Шаги** — одно действие на шаг
- **Ожидаемый результат** — наблюдаемый факт, не «должно работать»

Плохо: «Проверить логин».  
Хорошо: «При верных данных `standard_user` открывается каталог `/inventory.html`».

Плохо: «Система корректно обрабатывает ошибку».  
Хорошо: «Под полями красный баннер: `Epic sadface: Username is required`».

## Баг-репорт

Баг без шагов воспроизведения почти бесполезен.

Обязательные поля:

- Краткий заголовок: что сломано + где
- Окружение (браузер, ОС, URL, пользователь)
- Шаги
- Фактический результат
- Ожидаемый результат
- Серьёзность (см. ниже)
- Вложения: скрин или точный текст ошибки

На Sauce Demo всегда указывай **логин**. У `standard_user` и `problem_user` поведение разное. Если баг только у `problem_user`, это всё равно дефект с точки зрения пользователя этой роли — просто напиши это явно.

## Серьёзность

| Уровень | Когда ставим | Пример |
|---|---|---|
| Blocker | Нельзя начать работу | Не открывается сайт, нельзя залогиниться стандартным пользователем |
| Critical | Нельзя завершить покупку | Чекаут не отправляется, сумма считается неверно |
| Major | Сценарий ломается, есть обход | Сортировка не работает, поле фамилии не вводится |
| Minor | Мешает, но сценарий проходит | Кривая вёрстка, лишний отступ |
| Trivial | Косметика | Опечатка в подписи |

## Что не баг

- `locked_out_user` не входит — это **ожидаемое** поведение, если есть сообщение об ошибке
- Медленный вход `performance_glitch_user` — ожидаемая особенность роли (фиксируем как наблюдение, не как баг, пока нет требования «логин < 2 сек»)
- Сайт на английском

## Прогон

После выполнения кейса ставь статус:

- **Pass** — совпало с ожидаемым
- **Fail** — не совпало, есть баг
- **Blocked** — не смог выполнить из-за другого бага
- **Skipped** — сознательно не делал

Не ставь Pass «на глаз». Если не прогнал — так и напиши.
