# Тест-план: Sauce Demo

**Продукт:** Swag Labs (saucedemo.com)  
**Версия плана:** 1.0  
**Дата:** 2026-08-20  
**Тип тестирования:** ручное функциональное, смоук, негативное, исследовательское

## 1. Цель

Проверить, что покупатель может войти, выбрать товары, оформить заказ и выйти.  
Найти дефекты, которые мешают этому пути или вводят пользователя в заблуждение.

Не цель: «найти вообще все баги мира» или автоматизировать всё сразу.

## 2. Что в скоупе

- Логин и сообщения об ошибках
- Каталог: отображение 6 товаров, сортировка, добавление в корзину
- Карточка товара
- Корзина: состав, удаление, переход к оформлению
- Чекаут: обязательные поля, расчёт суммы и налога, завершение заказа
- Меню: Logout, Reset App State, All Items
- Защита внутренних страниц без авторизации
- Смоук на Chrome + беглая проверка узкой ширины экрана

Роли в скоупе:

- `standard_user` — полный функциональный прогон
- `locked_out_user` — только логин
- `problem_user`, `error_user`, `visual_user` — исследовательский прогон и баги
- `performance_glitch_user` — логин и один смоук-сценарий на задержку

## 3. Что вне скоупа (сейчас)

- Кросс-браузерный прогон Safari / Edge на всех кейсах
- Доступность (a11y) по WCAG целиком
- API, безопасность, нагрузка
- Мобильное приложение Sauce Labs
- Ссылка About (внешний сайт saucelabs.com) — только факт перехода

## 4. Подход

1. Сначала смоук-чеклист — жив ли магазин.
2. Потом позитивные кейсы `standard_user` по модулям.
3. Затем негатив: пустые поля, неверный пароль, прямые URL.
4. Затем роли с дефектами: оформляем баги, не путаем их со штатным поведением.
5. В конце — короткий исследовательский час без сценария.

Техника проектирования:

- Эквивалентные классы и граничные значения на полях логина и чекаута
- Позитив / негатив
- Состояние: пустая корзина, 1 товар, несколько товаров
- Сессия: логин, логаут, кнопка «Назад»

## 5. Окружение

| Параметр | Значение |
|---|---|
| URL | https://www.saucedemo.com |
| Браузер 1 | Google Chrome, последний стабильный |
| Браузер 2 | Firefox (смоук) |
| ОС | Windows 10/11 |
| Ширина | 1920×1080 и ~375px |
| Данные | стандартные демо-логины, пароль `secret_sauce` |

Тестовые данные выдумываем сами (имя, фамилия, индекс). Реальные паспортные данные не используем.

## 6. Критерии начала

- Сайт открывается
- Страница логина показывает список пользователей
- Есть доступ к браузеру и интернету

## 7. Критерии окончания

- Выполнен смоук
- Выполнены кейсы в `test-cases/` для `standard_user`
- По каждой роли с дефектами есть хотя бы заметка или баг-репорт
- Все найденные дефекты оформлены по шаблону
- В прогоне указаны pass / fail / blocked

## 8. Оценка рисков

| Риск | Влияние | Как снижаем |
|---|---|---|
| Сайт недоступен или изменился | Нельзя прогнать | Зафиксировать дату прогона и скрин |
| Путаем демо-баг с «настоящим» | Шум в отчёте | В баге писать роль и «воспроизводится на problem_user» |
| Слишком много кейсов | Не доделаем | Смоук + критичный путь важнее полного регресса |
